# OKRs (Objectives & Key Results)

OKRs are a powerful goal-setting framework that helps you define ambitious goals and track measurable progress. Used by Google, Intel, and thousands of other organizations, OKRs align teams around what truly matters.

## What are OKRs?

**OKR** stands for **Objectives and Key Results**:

```
OBJECTIVE: What do I want to achieve?
           (Qualitative, inspirational, memorable)

KEY RESULTS: How will I know I achieved it?
             (Quantitative, measurable, specific)
```

### Example OKR

**Objective**: Become the most trusted partner for our enterprise customers

**Key Results**:
1. Increase Net Promoter Score from 42 to 65
2. Achieve 95% on-time project delivery (currently 78%)
3. Reduce customer escalations by 50%
4. Obtain 5 customer case study testimonials

## Objectives

### What Makes a Good Objective?

| Quality | Description |
|---------|-------------|
| **Qualitative** | Describes a desired state, not a number |
| **Inspirational** | Motivates the team |
| **Memorable** | Easy to remember and rally around |
| **Aligned** | Connects to larger organizational goals |
| **Ambitious** | Pushes beyond comfort zone |

### Objective Examples

✅ **Good Objectives**:
- "Delight customers with world-class support"
- "Build a high-performance engineering culture"
- "Establish market leadership in the SMB segment"
- "Transform our data infrastructure for scale"

❌ **Poor Objectives**:
- "Increase revenue by 20%" (This is a Key Result)
- "Do good work" (Too vague)
- "Maintain current performance" (Not ambitious)
- "Complete Project X" (This is a task)

## Key Results

### What Makes a Good Key Result?

| Quality | Description |
|---------|-------------|
| **Quantitative** | Has a number |
| **Measurable** | Can be objectively verified |
| **Specific** | Clear definition |
| **Time-bound** | Within the OKR period |
| **Challenging** | 70% completion is good |

### Key Result Anatomy

```
[Verb] [Metric] from [Start] to [Target] by [Date]

Example: Increase NPS from 42 to 65 by end of Q2
```

### Key Result Examples

✅ **Good Key Results**:
- "Reduce average response time from 4 hours to 1 hour"
- "Launch 3 new product features with >80% adoption"
- "Increase conversion rate from 2.1% to 3.5%"
- "Achieve 99.9% uptime (currently 99.2%)"

❌ **Poor Key Results**:
- "Improve response time" (No target)
- "Launch some features" (Not specific)
- "Make customers happy" (Not measurable)
- "100% completion of all tasks" (Binary, not outcome-focused)

## Creating OKRs in Tracker

### Step 1: Create Objective
1. Navigate to **Pulse** → **OKRs**
2. Click **+ Add OKR**
3. Enter the Objective title
4. Add description (context, motivation)
5. Select owner

### Step 2: Set Time Period

| Period | Best For |
|--------|----------|
| **Quarterly (Q1-Q4)** | Most OKRs - standard cadence |
| **Annual** | Long-term strategic goals |
| **Custom** | Special projects or initiatives |

### Step 3: Add Key Results
For each Key Result:
1. Click **+ Add Key Result**
2. Enter description
3. Set Start Value (where you are)
4. Set Target Value (where you want to be)
5. Optionally set weight (importance)
6. Optionally link to data source

### Step 4: Link Data Sources
Key Results can auto-update from:
- **KPIs**: Live metric values
- **Projects**: Completion percentage
- **Manual**: You update the value

## Progress & Status

### Progress Calculation

**Individual Key Result**:
```
Progress = (Current - Start) / (Target - Start) × 100%
```

**Overall OKR**:
```
Progress = Weighted average of all Key Results
```

### Status Indicators

| Status | Progress Range | Meaning |
|--------|----------------|---------|
| 🟢 **On Track** | 70-100% | Likely to achieve |
| 🟡 **At Risk** | 40-69% | Needs attention |
| 🔴 **Off Track** | 0-39% | Significant risk |

### Why 70% is Success
OKRs should be **stretch goals**:
- 100% every time = not ambitious enough
- 70-80% = appropriately challenging
- <50% consistently = too ambitious or wrong focus

## OKR Best Practices

### Quantity
- **3-5 Objectives** per quarter maximum
- **2-4 Key Results** per Objective
- Quality over quantity always

### Cadence

| Activity | Frequency |
|----------|-----------|
| Set OKRs | Quarterly |
| Update progress | Weekly |
| Review status | Bi-weekly |
| Formal review | Monthly |
| Grade & reflect | End of quarter |

### Alignment
- OKRs should cascade: Company → Team → Individual
- Each level supports the level above
- But not every OKR needs to cascade

### Common Mistakes

| Mistake | Better Approach |
|---------|-----------------|
| Too many OKRs | Focus on 3-5 max |
| All committed (not stretch) | Include aspirational goals |
| No regular updates | Check weekly |
| Set and forget | Review bi-weekly minimum |
| Tie to compensation | Keep separate |

## OKR Workflow in Tracker

### Beginning of Quarter
1. Review previous quarter results
2. Set new OKRs
3. Link to data sources
4. Share with team

### During the Quarter
1. Update Key Result values weekly
2. Review overall status bi-weekly
3. Discuss in 1:1 meetings
4. Adjust if circumstances change

### End of Quarter
1. Final progress updates
2. Grade each OKR (achieved/not)
3. Reflect on learnings
4. Archive and start fresh

## Further Reading

### The OKR Origin Story
OKRs were created by Andy Grove at Intel in the 1970s and popularized by John Doerr at Google. The book "Measure What Matters" by John Doerr is the definitive guide.

### Key Principles
1. **Objectives** are aspirational
2. **Key Results** are measurable
3. **70% achievement** is success
4. **Transparency** across the organization
5. **Decoupled** from compensation
